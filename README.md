# 燕云面板模拟器

基于燕云培养助手的独立配装工具，保留战斗属性面板、流派心法、装备配置三个板块，配置变化实时更新面板。

当前主数据源为 **基础数值记录.xlsx（人物 100 级 / 大世界 24 级，南吕相和·上半赛季）**。Excel 是人工维护源，`src/data/game/` 中的六份中文 JSON 是同步后的程序数据。母项目提供武器名称和词条池，DIY 表作为可选参考。原始 Excel 不会被脚本修改。

## 使用

```powershell
npm install
npm run dev
```

打开 http://localhost:3100 。构建静态页面用 `npm run build`。发布到主站 `/panel/` 使用 `npm run build:panel`，Pages 输出在 `dist/panel/`，根入口自动跳转。登录 Cloudflare 后执行 `npm run deploy`，项目名为 `maoye-panel-simulator`；`maoye-router` 将 `/panel/` 请求转发到该 Pages 项目，`maoye-world` 提供入口。

PC 使用固定单屏布局，左侧战斗属性、右侧八件装备，不滚动页面。标题下的横条依次选择流派、心法、弓玦套装、武器套装；流派和心法通过弹窗配置，横条显示已选结果。手机通过底部标签切换战斗面板、武器四件、防具四件，装备编辑使用底部弹出面板，长列表只在弹窗内部滚动。

战斗属性支持图表 / 表格切换：攻击区间用统一刻度，判定有效率按精准 100%、会心 80%、会意 40% 上限绘制圆环，颜色由红经黄过渡至绿，增伤和穿透分组显示。增伤与穿透固定两栏三行，每页六项；多余项目翻页，保持容器尺寸固定。装备左半区为主武器、副武器、环、佩，右半区为冠胄、胸甲、胫甲、腕甲。

- 先选流派，再选最多四本心法、套装和装备词条。
- 八件装备各有宫商角徵羽和定音，共 48 槽；支持搜索、满值填充、微调、承音、清空、保存后编辑下一件。
- 商角徵羽不能重复，最多两条属性攻击；五音完整后解锁定音，六槽完整后可承音。
- 装备和心法编辑需应用才保存，取消不改变配装；切换流派保留兼容配置。
- 主界面提供“新建方案”“保存方案”和未保存状态。编辑只自动保留为本机草稿，点击保存才更新已存方案；刷新优先恢复草稿，包括空白新方案。切换或重新载入前处理未保存修改，新建时可另存当前配装。复制、导入不会切走当前编辑内容；本地删除可在方案管理中恢复。导出已存方案与导出当前配装分别提供。
- 数值更新后按新总表重新计算；重新载入配装时，超出新范围的词条值会限制到新范围。旧配装的防御词条和防具套装会忽略，旧单体 / 群体奇术神力会统一为全奇术增伤；过滤后五音不完整的部位需重新补齐，才能使用定音及承音。
- 增益括号表示敌人抗性折算后的有效值，直接会心与直接会意另列。无相攻击已计入本系属攻总值，绿色 `（+数值）` 标出其中的无相贡献，不再单独展示无相攻击。本系伤害加成参与计算但不展示。
- 判定圆环为有效值，下方为白字三率；超出满有效值所需白字量时展示溢出。当前抗性下精准 / 会心 / 会意白字上限分别为 163% / 224% / 112%。
- 只计算攻击、判定、穿透与增伤，保留劲 / 敏 / 势；移除气血、防御、抗性、体 / 御以及治疗 / 护盾属性。保留八件装备，用户只选弓决和武器套装。
- 宫为金色，商角徵羽为蓝色，定音为绿色，与母项目槽位颜色一致。

## 分享图、夜间模式与账号同步

标题右侧可切换夜间模式（记住选择），生成米色纸张、墨绿标题和品质心法的竖版分享 PNG，顶部突出攻击与三率，装备左右成列。“属性名片”展示流派、心法套装与核心面板，适合聊天分享；“装备详录”额外包含八件装备和全部 48 槽。两种始终使用浅色纸张。

账号沿用培养助手的 Supabase 服务，用户名去除首尾空格并统一小写，沿用其账号映射。服务端保障映射邮箱唯一；前端识别重复注册错误和空 identities 的模拟成功响应，提示改为登录，并阻止重复提交。配置方式：

1. 将 `.env.example` 复制为 `.env.local`，填写培养助手的 `VITE_SUPABASE_URL` 和公开的 `VITE_SUPABASE_ANON_KEY`，然后重启开发服务或重新构建。不要填写 service_role 密钥。
2. 在该 Supabase 项目的 SQL Editor 执行 `scripts/supabase-init.sql` 一次，创建独立的 `panel_simulator_plans` 表及仅限本人访问的策略；不写入培养助手原有方案表。
3. 在方案管理中登录。“从云端下载”只读取云端，选中方案后下载到本地；与本地内容不同的同 ID 方案会先保留本地副本，当前草稿保持原样。“上传到云端”只上传所选的已保存方案，列表会标出覆盖项；未保存草稿和本地删除记录均不上传。如果云端版本在预览后变化，上传会停止并要求重新查看列表。切换账号后需重新打开传送列表；登录和退出本身不传送方案。

未配置服务时，本地方案功能照常使用，注册登录入口显示待连接。本机已在被 Git 忽略的 `.env.local` 配置培养助手的服务。独立方案表已创建并可访问；实际登录及跨设备同步须使用用户账号验证。

## 按来源记录数值

| 来源 | JSON 文件 | 记录方式 |
| --- | --- | --- |
| 八件装备的 48 个可变词条 | `装备词条.json` | 范围、承音值和候选池；实际选择与数值存在玩家配装里 |
| 等级、人物天赋、武库、蹊跷、叠音 | `基础属性.json` | 每个来源单独记录；武库映射到本系攻击 |
| 武学天赋 | `流派.json` | 天赋总表＋各流派属性清单、武器与需求类型 |
| 心法 | `心法.json` | 五类数值总表＋每本心法的归属、品质与属性清单 |
| 装备套装 | `套装.json` | 额外加成总表＋每套的加成属性清单 |
| 转化及折算规则 | `规则.json` | 五维转化、抗性、数据来源与缺项说明 |

装备白值分为武器白值和防具白值，先加入基础面板。套装页的攻击包含白值，同步时扣除白值，只留下套装额外效果。没有选择套装也保留已穿戴八件装备的白值。叠音、可变词条和套装额外效果各计一次。

劲 / 敏 / 势转化后吸收无相攻击及穿透，再计入武学天赋及需求折算，最终计算有效值。敌人的判定抗性和增益抗性用于攻击属性折算，仍保留为计算规则。

**属性百分比统一用百分数点数：`16.2` 表示 `16.2%`。** 攻击、劲敏势和穿透用实际数值；倍数规则如增益抗性 `0.3225`、承音比例 `0.94` 用小数。

## 心法：总表与明细

`心法.json` 的 `数值总表` 分五类：金色本流派、紫色本流派、金色通用、紫色通用、蓝色通用。空白字段表示未记录，不能自动当作零值或借用另一类数值。

每本心法通常只需要记录：

```json
"扶摇直上": {
  "归属": "破竹鸢",
  "品质": "金色",
  "属性": ["最小外功攻击", "直接会心率"]
}
```

它从金色本流派总表取最小外功攻击 130.1、直接会心率 4.6。不会把该类的整行属性都加给这本心法。修改公共数值后，引用该字段的心法一起更新。

`归属: "通用"` 使用通用品质总表；其他已记录的专属归属使用本流派品质总表。**“本流派”指心法本身的专属归属，不随当前选择流派动态改变数值。** 跨流派装备仍使用该心法原有品质数值。界面分组由归属生成，不用另维护分组名单。

只加最小攻击，与同时加攻击上下限，是两种不同字段。后一种通过 `取值` 明确对应关系：

```json
"三穷致知": {
  "归属": "破竹鸢",
  "品质": "紫色",
  "属性": ["最小外功攻击", "最大外功攻击", "外功伤害加成"],
  "取值": {
    "最小外功攻击": "外功攻击下限",
    "最大外功攻击": "外功攻击上限"
  }
}
```

属性攻击同理：总表中属性攻击下限 / 上限为 22.1 / 44.3，单项最小 / 最大属性攻击为 66.4。程序把鸣金、裂石、破竹、牵丝、无相属性名对应到公共属性字段。

确实不同的例外使用 `数值覆盖`，例如无名心法的最大外功攻击 121.3。它只影响该心法，不改公共总表。无固定加成且品质未记录的心法，品质留空；怒斩马为通用紫色心法，不提供攻击属性加成。归燕经、婆娑影、丹心篆不再收录；旧方案加载时会移除这三本心法，保留其他配置。

## 武学天赋与套装：总表与明细

`流派.json` 的 `天赋总表` 集中保存外功攻击、判定率、本系攻击、穿透和增伤。`五维需求值` 统一保存 492；流派只记录需求的是劲、敏还是势，以及获得哪些 `天赋属性`。武器、属性需求仍各自记录，不因公共数值相同而合并不同的流派规则。

例如破竹鸢获得最小外功攻击、会心率、最小 / 最大破竹攻击、破竹穿透、破竹伤害加成；鸣金虹选择最大外功攻击和会意率。本系名称对应到总表的属性攻击、属性穿透和属性伤害加成。

`套装.json` 的 `数值总表` 集中保存额外攻击、判定率和弓决加成。每套只记录 `加成属性`；弓决通过 `取值` 使用自己的公共字段。时雨按记录表只加精准，不继续带入旧参考表的额外会心伤害。

两者都可使用必要的单项覆盖：天赋用 `天赋覆盖`，套装用 `数值覆盖`。防具套装不参与攻击面板，也不提供选择入口。套装稳定键用于配装保存，不要随意改名。

## 游戏更新后同步

在 Excel / WPS 中更新总表或明细，重新计算并保存，再在项目目录执行：

```powershell
# 先看差异，不写入
python scripts/import_excel.py '基础数值记录.xlsx'

# 同步到六份 JSON
python scripts/import_excel.py '基础数值记录.xlsx' --world-level 24 --season '南吕相和·上半赛季' --write

# 静态发布页面需重新构建；开发预览会自动刷新
npm run build
```

当前 Excel 表头仍写大世界 20 级，以上命令按用户确认覆盖为 24 级和当前赛季，仅更新版本信息，不猜测成长数值。后续修正表头后可省略 `--world-level`；`--season` 用于更新赛季。

脚本只用 Python 3 标准库，无需额外依赖；`--source record` 可省略。它保留心法、天赋和套装的已知总表引用，修改公共数值不需要逐项改几十本心法。新增心法若未记录归属与品质，可先在 JSON 中补齐，后续同步保留其归属信息。

也能直接修改 JSON 总表，无需改计算代码。再次同步 Excel 会以表格为准覆盖字段，因此长期记录请同步维护到 Excel。

脚本针对当前表格布局：心法总表在第 34～55 行，天赋总表在第 30～38 行，套装白值与加成在现有区域。心法及天赋的直接引用、套装的已知引用相加直接读取总表，其余公式读取保存的计算结果。**它不是通用 Excel 公式引擎。** 更改工作表名称、总表位置或公式结构时需调整脚本；关键布局变化或缺少公式缓存会提示。

如需明确改用 DIY 参考值：

```powershell
python scripts/import_excel.py 'DIY计算器0.10.2.xlsx' --source diy
python scripts/import_excel.py 'DIY计算器0.10.2.xlsx' --source diy --write
```

DIY 模式用逐项覆盖，不反推或改写品质总表；重新同步记录表会恢复表中项目的公共引用。默认以自己的记录表为准。页面“导入配装”只导入玩家配置，与 Excel 数值同步不同。

## 当前值与缺项

- 劲 / 敏 / 势为等级 262＋人物天赋 42，每项共 304；劲转最小外攻按 0.225。
- 成长、人物天赋、蹊跷、叠音的外攻共 1010.6～1822，装备白值另加 380～757；随后再加五维转化。
- 词条范围和明确承音值来自最后一页，例如外攻承音 131.3、会心承音 15.2%。没有承音记录的字段不保留旧承音数字；仅五音承音时使用承音范围，定音仍使用自己的范围。
- 已同步记录表 50 本心法、11 个流派的天赋以及攻击套装表，完整配装支持 11 个流派。破竹樽主武器拳甲（手甲）、副武器双刀，对应手甲武学增伤 / 双刀武学增伤，选择时默认武器套装为倾觞。
- 破竹樽防具定音目前只有用户提供的“悬身断水·浓醺技能增伤”，范围沿用防具招式定音公共范围。冠胄、胸甲神力统一为全奇术增伤。
- 增益抗性沿用旧值。岳山倾缺攻击面板加成，暂不计加成。这些不是最新游戏实测值。防御属性会在每次同步时过滤，Excel 原表不修改。
- 候选词条池仍来自母项目，合并调律、转律与稀有候选，用于复现装备；不模拟转律次数或跨流派转律过程。
- 不包含伤害、输出轴、触发技能、食物符帖等临时增益或毕业度评价。

已逐项对照记录表的 50 本心法、11 个已支持流派的天赋，以及有数值的套装。已检查修改公共总表后相关心法、天赋、套装一起改变，不被明细的旧公式缓存覆盖。

例：破竹鸢，扶摇直上 / 易水歌 / 擒天势 / 断石之构，弓诀·惊弦、撼天，无装备可变词条，外功攻击 **2126.3634～3352.84**，劲 / 敏 / 势每项 304。这是按当前记录表计算的结果，不再用旧 DIY 默认结果作同口径对照。

## 代码位置

- `src/domain/panel.js`：面板计算。
- `src/stores/simulator.js`：配装、槽位约束与配置导入。
- `src/data/templateStats.js`：按属性清单从总表取值，处理字段映射与明确覆盖。
- `src/data/*.js`：读取 JSON，提供计算与界面所用属性。
- `scripts/import_excel.py`：记录表 / DIY 数值同步。
